# PILOT-FIX-01 — reported learner usability and speech defects

Authority: the product owner's ten reported app issues on 25 September 2026.
Bounded bug-fix follow-up to STUDENT-CONVERSATION-02 and ADR-0025/0026/0042.
Existing uncommitted pilot implementation is preserved. The initial local-only
record below is superseded by the connected-phone and deployment follow-ups.
No real learner microphone audio was processed during these follow-ups.

## Delivered behavior

- App name matches the logo's CSS height. Phone headers wrap; short landscape
  keeps both smaller together. Existing 200% text/reflow tests remain enforced.
- Account menu measures its trigger and clamps its position within the viewport;
  scrolling/resizing repositions it. Links and buttons have consistent targets.
  Escape closes the menu and restores trigger focus.
- Suppress the browser's touch highlight and pointer-only focus outline while
  preserving visible keyboard focus.
- Dark Home streak and bottom navigation use matching dark surfaces and readable
  foregrounds, including unselected destinations.
- Account deletion instructions have a prominent top-level Back to app link.
  This does not submit an erasure request or alter deletion authority.
- Learn/interactive speaking screens own one Type instead fallback. Nested
  recorder permission/error panels can omit the duplicate; transcript repair is
  labelled Edit what you said rather than a second unrelated Type instead.
- Drill guidance already quotes the exact model on a mismatch. When that
  guidance plays, the client does not speak the same model again. A failed
  guidance playback retains model-audio fallback. The existing deterministic
  repeat-the-model lesson exercise remains distinct from free conversation.
- Completing Practice no longer requires a volatile in-memory Check result:
  the server still verifies its saved passed Check. An accepted completion
  updates the UI without requiring a second detail request to succeed. Completed
  sessions offer Continue with the next session name. Rejected completions do
  not unlock Conversation. Existing subscription/session access rules remain.
- Original English role-play transcription sends an explicit en-IN input hint;
  multilingual question help retains configured automatic detection. Returned
  locale/source provenance remains intact, with existing repair safeguards.
  This uses the provider's documented input-language field:
  [Sarvam STT reference](https://docs.sarvam.ai/api-reference/speech-to-text/transcribe).
- Dialogue prompt v5 explicitly requests the AI partner's next meaningful line
  after an accepted answer, without parroting the learner. Corrections still
  intentionally speak the corrected learner sentence and require a retry.
  Prompt changes and mocked tests are not proof of live model/recognition quality.

### Live failures investigated and resolved

- An en-IN input hint alone was insufficient: the live provider returned the
  known English guest fixture in Devanagari while labelling it en-IN. A bounded
  diagnostic comparison found `codemix` returns the same words in Latin script.
  English role-play now requests codemix; it never requests translation for
  original-speech assessment. Other modern question-help retains verbatim mode.
  Returned locale/source remain provider provenance. A new mocked regression
  proves an en-IN hint does not relabel actual Hindi speech as English.
  The usage model suffix records the actual requested mode.
  [Official mode reference](https://docs.sarvam.ai/api/api-guides-tutorials/speech-to-text/how-to/select-output-mode).
- Prompt v5/v6 live checks exposed grammatical acceptance being confused with
  completing scenario goals. A correct retry was first unassessed, then wrongly
  corrected solely to add a greeting. Prompt v7 makes missing greetings, names
  or appointment details follow-up questions, never grammar errors. It explicitly
  assesses the current retry independently from the older mistake. Existing
  output validators, objective evidence and deterministic learning gates remain.
- Final live web check: incorrect synthetic clinic sentence → English correction
  and retry; corrected sentence → accepted/awaiting_reply and the receptionist's
  next question without echo. Two turn requests, no page errors; narrow layout
  and public download link pass. Only this run's sessions were exited/cleaned up.
- Final live STT: the existing 2.31-second synthetic guest fixture produces English
  script, en-IN, original_speech, with the expected word; latency 678 ms for this
  one adapter request. This is not a representative learner/latency benchmark or
  proof of end-to-end microphone accuracy.
- Physical read-only progression inspection: Introduction is complete, Practice
  is incomplete and Conversation locked. Practice opens its first unanswered
  Check question. A scripted completion attempt did not reach the hidden action
  while that question was open; it timed out. No answers, scores or completion
  were fabricated. The resumed passed-Check completion path has regression
  coverage; this phone observation does not prove whether an older Check exists.

- Final physical Android check: AI-only clinic opening, one typed synthetic
  English answer accepted, and the next partner line displayed without echo.
  The test used no microphone, exited its own session, returned to Home and
  restored the prior Kannada interface/dark theme. ADB installation was not
  repeated because the installed bundle already contains the UI fixes.
